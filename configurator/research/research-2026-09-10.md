## Recommendation
Pick OpenAI `gpt-5.4-nano` in non-reasoning mode with Responses API `text.format` json_schema `strict:true`: it is the cheapest verified model that has image input (logo/photo), first-class strict JSON schema, and the best measured no-reasoning latency (~0.8 s TTFT, 158 t/s → ~2.7 s per 300-token call); ~$0.007 per 10-call session, so cost is negligible. `gpt-5-nano` is 3x cheaper still ($0.002/session) with near-identical latency if the older model's quality is adequate. Strongest alternative: Groq `openai/gpt-oss-20b` with `strict:true` constrained decoding at `reasoning_effort: low` — same $0.002/session and ~1000 t/s generation (0.3 s for 300 tokens), but text-only, so the logo must be passed through as an asset reference rather than inspected; if vision is truly optional, this is the fastest choice. Claude Haiku 4.5 works (structured outputs, vision) but is 4–15x the price ($0.03/session) and the slowest generator (78 t/s, ~4.6 s per call), so it is not the fit here. Gemini 3.1 Flash-Lite is cost-competitive but its 5.3 s TTFT with thinking on must be disproven with thinking off before use.

## Integration options on Vercel + Next.js

1. **Subpath (`/design`, `/configure`) — supported, two ways.**
   a. *Same project:* add a route to the existing Next.js app. Cleanest URL, shares layout/fonts, but needs access to the site's repo and each configurator deploy redeploys the marketing site.
   b. *Rewrite/reverse proxy:* add to the site's `vercel.json` (or `next.config` rewrites) `{ "source": "/design/:path*", "destination": "https://<configurator-host>/design/:path*" }`. Vercel documents this as the "microfrontends" use; browser URL stays on www. Caveats: the configurator must serve under `basePath: '/design'` (asset URLs), and external-rewrite caching is on by default for projects created after 2026-04-06 (set `x-vercel-enable-rewrite-caching: 0` if the app is dynamic). Source: https://vercel.com/docs/routing/rewrites
2. **Subdomain (`design.screenery.design`) — supported, least effort.** Create a separate Vercel project, add the domain in Settings → Domains, add one **CNAME** at Porkbun (`design` → the CNAME Vercel shows, e.g. `cname.vercel-dns.com`). SSL is automatic; a subdomain can live in a different project from www; no change to the marketing site at all. Hobby limit 50 domains/project. Source: https://vercel.com/docs/domains/working-with-domains/add-a-domain
3. **iframe embed — possible but weakest.** The marketing site would still need a code change (new section/page hosting the iframe), the configurator must not send `X-Frame-Options: DENY`, and a full-screen 3D/2D configurator inside an iframe gives worse mobile/URL/state handling. Only sensible if the owner cannot touch the site repo and wants it "on the page".

Note: Squarespace/Webflow-style "code injection" does not apply; this is a custom Next.js codebase, so any on-domain change means a commit to that repo.

## Recommendation
Pick option 2: deploy the configurator as its own Vercel project on `design.screenery.design` (or `app.`), add one CNAME at Porkbun, and later add a single nav/CTA link on the marketing site. It is zero-risk to the existing site, needs no access to its repo, and the subdomain is currently unclaimed. Strongest alternative: option 1b — a `vercel.json` external rewrite from `/design/:path*` on www to the configurator host with `basePath: '/design'`, which keeps one domain and shares cookies/SEO, at the cost of one small commit to the site repo and care with rewrite caching. Match the look with `#8b7355`/`#c4a97d` accents on `#fafaf8`, Helvetica Neue-stack, light weights, uppercase tracked labels.

## Recommendation
(a) Artwork/style regeneration from the 3D reference render: gpt-image-2.5-sunburst with `input_fidelity: high`, render as image 1, style refs after it, quality high (≈$0.05–0.2/image), because it has the strongest documented reference/product preservation and a real mask for the panel faces; Nano Banana Pro (gemini-3-pro-image, $0.134, 14 refs) is the strongest alternative and faster, but has no mask and stamps SynthID. ## 2. space-v30 schema
Ply record keys (references/space-v30/assembly-geometry.json): id, part_id, role (front/middle/back/door-back), vertices_mm [[x,y,z]], triangles [[i,j,k]], artwork[], cut_lines_mm, cut_loops_mm, explode_z_direction, machining[{source_id, kind bevel|hinge, remainder_mm, depth_mm, removed_volume_mm3}], source_faces, glue_depth_mm, matrix_world (4×4), installed.
- **Vertices are already world space** (Y up, mm, floor y≈0). The viewer never reads matrix_world; ply bbox centre ≠ matrix translation; connector plies lie in the YZ plane while matrix_world carries the rotation. All plies of a part share one matrix_world, so parts can be re-localised by inverting it.
- Artwork entry: image ('artwork/art-N.png', relative), sha256, vertices_mm, triangles, uv, surface_z_mm, layer_order, clip_uv_to_source_bounds. Overlay sits 0.02–0.03 mm off the face. UV is an exact affine of in-plane mm (max residual 3e-11 over all 31 plies), and ranges exceed [0,1] (e.g. u −0.89..0.91); the viewer discards fragments outside [0,1] via a shader patch. Inverting the affine gives the image rectangle in mm (art-15 → x −854.7..−545.0, y −7.9..934.3) — this is the "artwork slot as UV rectangle" data.
- cards.json (schema screenery.planar-cards/v1): parts[{id,title,status,quantity,plies[{role,thickness_mm,material_card_mm Polygon,material_glue_mm,source_to_card_mm affine,artwork_node_paths,artwork_mask_source_mm,machining,slots[{width_mm,mouth/base}] ,hinge_source_id}]}]. No `kind` field except zurich.
- Mesh budget: 547k body tris / 273k verts (8 connector plies = 32.8k tris each ≈ 48%), 294k overlay tris; contours are bezier-flattened at ~1 mm.

- Canonical docs: https://docs.magnific.com (sitemap https://docs.magnific.com/llms.txt; any page + `.md` gives raw markdown). `https://docs.freepik.com/introduction` now 301-redirects to `https://docs.magnific.com/introduction` (observed via fetch).
- OpenAPI spec (single best source, 1.3 MB): https://storage.googleapis.com/fc-freepik-pro-rev1-eu-api-specs/magnific-api-v1-openapi.yaml — server `https://api.magnific.com`.
- There is no separate "Magnific AI API": the old magnific.ai upscaler/relight/style-transfer are endpoints of this API ("Magnific.ai is part of Magnific... same technology" — https://docs.magnific.com/api-reference/image-upscaler-precision/image-upscaler).
- Freepik rebranded to Magnific in April 2026; third-party guide (updated 2026-09-03) says `api.freepik.com` and `api.magnific.com` are both live, one key works on either, header is `x-freepik-api-key` or `x-magnific-api-key` "depending on which endpoint your key is configured for" (https://apiframe.ai/guides/freepik-api-guide). A "6-month deprecation window with deprecation headers" claim appeared only in a search snippet; magnific.com/ai/docs pages returned 403 to me — unverified.

## Auth
- Header `x-magnific-api-key: <key>`; base `https://api.magnific.com/v1`; server-to-server only (https://docs.magnific.com/authentication.md).
- Keys: https://www.magnific.com/user/organization/api-keys (admin email). Webhook secret is issued at key creation (https://docs.magnific.com/webhooks.md). Key prefix "MS": not documented — unverified.

## Async task + webhook flow
- POST returns `{data:{task_id, status}}`; status enum `CREATED|IN_PROGRESS|COMPLETED|FAILED`; `GET /v1/ai/<tool>/{task-id}` → `{data:{task_id,status,generated:[url,...]}}`; `GET /v1/ai/<tool>` lists tasks (spec).
- `webhook_url` (optional on every AI POST): called on each status change; "payload... is the same as the corresponding GET endpoint response, but without the data field" (spec) — i.e. flat `{task_id,status,generated}`.
- Verification (https://docs.magnific.com/webhooks.md): headers `webhook-id`, `webhook-timestamp`, `webhook-signature`; sign `"{webhook_id}.{webhook_timestamp}.{raw_body}"` with HMAC-SHA256(secret) → base64; header is space-delimited `v1,<sig> v2,<sig>`; accept if any matches. Retry policy and timestamp tolerance: not documented.
- Uploads: `POST /v1/ai/uploads/request-url {"files":[{"content_type":"image/png"}]}` → per file `upload_url` (pre-signed PUT, `expires_in` 120 s), `headers` (must send all), `file_id`, `asset_url` (~24 h). Reference by `file_id` or `asset_url` (spec).
- Repo already implements poll-based flow with uploads: `/Users/za/Documents/screenery fresh codex/output/raffles-artwork-300dpi/magnific_upscale.py` (route `/v1/ai/image-upscaler-precision-v2`, settings sharpen 3, smart_grain 0, ultra_detail 0, flavor photo, 6 concurrent tasks, 15 s poll).

## Input/output limits
- Inputs: precision-v2, relight, style transfer, skin enhancer accept public HTTPS URL or base64; creative upscaler, precision v1, mystic references, expand: base64 only (spec). Docs recommend sending original bytes/URL, not canvas re-encodes.
- Creative upscaler: "resulted image can't exceed... 25.3 million pixels" (spec). Precision-v2: no limit stated; repo receipt shows outputs up to 5174×9544 and a self-imposed ≤10060 px/side tiling — empirical, not documented (`output/raffles-artwork-300dpi/magnific-receipt.json`).
- Receipt gotcha: precision-v2 with `scale_factor: 4` returned exactly 2×; the job chained 2× passes.
- Remove background: JPG/PNG ≤20 MB, output ≤25 MP, response URLs valid 5 min. Output-URL expiry for upscaler/relight/style tasks: not documented (video 24 h) — download immediately.

## Pricing
- API always bills credits; web "Unlimited" plans do not cover API (https://docs.magnific.com/pricing.md). EUR-per-credit: not found.
- Endpoint FAQs (docs): upscaler priced by output area — 1280×960 €0.10, 2560×1920 €0.20, 5120×3840 €0.50, 5120×2880 €0.40, 3840×2160 €0.20; relight €0.10 fixed; style transfer €0.10 fixed. Precision-v2, skin enhancer, mystic, remove-bg: no API price published.
- Third-party: new accounts get €5 free credit, pay-as-you-go (apiframe). Web-app credit table (magnific.com/ai/docs/ai-image-generator-credits, read via browser): Mystic 2.5 50 credits/image, Magnific One 130–1050 — web-app rates, not confirmed for API.

## Rate limits (https://docs.magnific.com/ratelimits.md)
- Per IP: 50 req/s (5 s window) and 10 req/s averaged over 2 min. Per key: 30,000 RPM. No daily cap except listed prompt/search services. Response header names not documented.

## Capability table (all async unless noted; all under https://api.magnific.com)
| Capability | Endpoint | Key params | How we'd use it |
|---|---|---|---|
| Upscaler Precision v2 | `POST /v1/ai/image-upscaler-precision-v2`, `GET .../{task-id}` | image (URL/b64), scale_factor int 2–16 or string "2".."16", sharpen 0–100 (7), smart_grain (7), ultra_detail (30), flavor `sublime|photo|photo_denoiser` | Mockup → print-quality preview without hallucination; reuse repo script; request 2× per pass. |
| Upscaler Precision v1 | `POST /v1/ai/image-upscaler-precision` | b64 only, no scale_factor field, sharpen 50 | Skip; use v2. |
| Upscaler Creative | `POST /v1/ai/image-upscaler`, `GET .../{task-id}` | b64, scale_factor `2x|4x|8x|16x`, optimized_for (`art_n_illustration`, `3d_renders`, …), prompt, creativity/hdr/resemblance/fractality −10..10, engine `automatic|magnific_illusio|magnific_sharpy|magnific_sparkle`; ≤25.3 MP | Artwork enlargement where invented detail is acceptable. "Sharpy" is an engine value, not an endpoint. |
| Relight | `POST /v1/ai/image-relight`, `GET .../{task-id}` | image; one of prompt / transfer_light_from_reference_image / transfer_light_from_lightmap; light_transfer_strength (100); change_background (true, "useful for product placement"); preserve_details (true); style enum; advanced_settings (whites…saturation, engine, transfer_light_a/b, fixed_generation); €0.10 | Product into room photo: room as reference image, change_background true, preserve_details true. |
| Style Transfer | `POST /v1/ai/image-style-transfer`, `GET .../{task-id}` | image + reference_image (both required), prompt, style_strength (100), structure_strength (50), flavor `faithful|…|donotstyle_sharp`, engine `balanced|definio|illusio|3d_cartoon|colorful_anime|caricature|real|super_real|softy`, fixed_generation; €0.10 | Artwork restyle; raise structure_strength to keep layout. |
| Skin Enhancer | `POST /v1/ai/skin-enhancer/{creative|faithful|flexible}`, `GET /v1/ai/skin-enhancer[/{task-id}]` | image, sharpen (0), smart_grain (2), skin_detail (80, faithful), optimized_for (flexible) | Portraits only; not needed. |
| Mystic (text-to-image) | `POST /v1/ai/mystic`, `GET /v1/ai/mystic/{task-id}` | prompt, resolution `1k|2k|4k`, aspect_ratio enum, model `realism|fluid|zen|flexible|super_real|editorial_portraits`, engine, structure_reference/style_reference (b64) + structure_strength/adherence/hdr, creative_detailing, fixed_generation | Generate room scenes or mockup bases. |
| Remove background | `POST /v1/ai/beta/remove-background` (sync, form-urlencoded `image_url`) | JPG/PNG ≤20 MB; returns original/high_resolution/preview/url, 5-min URLs | Cut product for compositing before relight. |
| Reimagine | `POST /v1/ai/beta/text-to-image/reimagine-flux` (beta, sync per spec) | image b64, prompt, imagination `wild|subtle|vivid`, aspect_ratio | Variations; spec-only, not in docs sitemap. |
| Image expand | `POST /v1/ai/image-expand/flux-pro` | image b64, prompt, left/right/top/bottom 0–2048 | Extend room backdrop. |
| Change camera | `POST /v1/ai/image-change-camera` | HTTPS URL, horizontal_angle 0–360, vertical −30..90, zoom 0–10, seed, output_format | Alternate mockup angles. |
| Uploads | `POST /v1/ai/uploads/request-url` | files[].content_type | Feed large local PNGs by URL instead of base64. |

## Recommendation
Use api.magnific.com with `x-magnific-api-key`, the OpenAPI YAML as the contract, and the existing `output/raffles-artwork-300dpi/magnific_upscale.py` (uploads + precision-v2 + polling) as the base; add a webhook receiver that verifies HMAC-SHA256 over `id.timestamp.body` against the `webhook-signature` header. Upscale mockups with Precision v2 (2x passes, flavor photo), relight products with `/v1/ai/image-relight` using the room photo as reference and `change_background: true`, and restyle artwork with `/v1/ai/image-style-transfer`. Strongest alternative: Upscaler Creative with `optimized_for: art_n_illustration` when invented detail is acceptable and 25.3 MP output is enough.

## Open questions
- Key prefix 'MS' is undocumented; confirm the key is accepted on api.magnific.com with x-magnific-api-key (third-party says header depends on which host the key was issued for).
- The 6-month api.freepik.com deprecation window and deprecation headers came only from a search snippet; magnific.com/ai/docs/freepik-is-now-magnific returned 403 — verify in a browser.
- EUR-per-credit rate and whether the endpoint-FAQ EUR prices (upscaler €0.10–0.50, relight/style €0.10) still apply under the credit model; precision-v2, skin enhancer, mystic, remove-bg API prices unpublished.
- Precision-v2 returned 2x when scale_factor 4 was requested (repo receipt); test string '4' vs integer 4 and confirm max output size (25.3 MP limit is stated only for Creative).
- Expiry of `generated` URLs for upscaler/relight/style tasks is undocumented (remove-bg 5 min, video 24 h, uploads ~24 h).
- Webhook retry policy and accepted timestamp skew are undocumented; rate-limit response header names are undocumented.
